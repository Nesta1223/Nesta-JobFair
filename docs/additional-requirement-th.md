# Additional requirement: ป้องกันเวลาสัมภาษณ์ทับซ้อน

ผู้ใช้คนเดียวกันต้องไม่มีรายการสัมภาษณ์ที่ช่วงเวลาทับซ้อนกันในวันเดียวกัน แม้จองกับคนละบริษัท กฎเดิมจองได้สูงสุด 3 รายการยังคงใช้ด้วย

- เก็บ `interviewDate`, `startTime`, `endTime` โดยเวลาเป็น `HH:mm` ตามเวลาไทย
- ช่วงใหม่ทับซ้อนเมื่อ `newStart < oldEnd && newEnd > oldStart`
- 09:00–09:30 กับ 09:15–09:45: ปฏิเสธด้วย HTTP 409
- 09:00–09:30 กับ 09:30–10:00: อนุญาต เพราะปลายช่วงไม่รวมอยู่ในช่วงเดิม
- คนละผู้ใช้หรือคนละวันสามารถใช้เวลาเดียวกันได้
- ตรวจทั้ง POST และ PUT; เมื่อแอดมินแก้ ต้องตรวจตารางของเจ้าของ booking และไม่นับ booking ที่กำลังแก้เป็นรายการซ้ำ
- `occupiedMinutes` และ unique index ที่ฐานข้อมูลป้องกันคำขอพร้อมกันผ่านเงื่อนไขได้ทั้งคู่

- Sequence update: ตรวจ owner/admin → ตรวจช่วงเวลาของเจ้าของโดยยกเว้นรายการปัจจุบัน → บันทึก หรือปฏิเสธ 409

## ตัวอย่างเดโมเพิ่มเติม

ใช้บัญชีทดสอบใหม่และ company ID จริงจาก GET companies:

1. POST booking วันที่ `2022-05-10`, `startTime: "09:00"`, `endTime: "09:30"` → 201
2. POST อีกบริษัท วันเดิม `09:15`–`09:45` → 409
3. POST อีกบริษัท วันเดิม `09:30`–`10:00` → 201
4. PUT รายการที่สองเป็น `09:20`–`09:50` → 409 และข้อมูลเดิมยังอยู่
5. แอดมินแก้รายการเดียวกันให้ทับซ้อน → 409 เช่นกัน

ชุด Postman เดิมใช้การจองแบบระบุวันอย่างเดียวเพื่อความเข้ากันได้ ค่าที่ไม่ส่งเวลาตอนสร้างจะเป็น 00:00–24:00 จึงควรใช้ body ที่ระบุเวลาในการเดโมข้อกำหนดเพิ่มนี้โดยเฉพาะ
